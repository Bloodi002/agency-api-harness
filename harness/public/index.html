How a QA run goes

  1. In the SIT web app, sign in as a tenant admin (or agency admin) and open Settings › API Credentials. Create a credential with the scopes you are testing and copy the client secret; it is shown once.
  2. Open the SDK explorer, choose Tenant or Agency, enter that credential, then pick any operation, fill in its fields and select Run with the SDK. You see what the SDK returned or threw, every HTTP call it made, and the same call as Node code.
  3. Run SDK checks with the same credential for the standard behaviour suite.
  4. For webhooks, create an inbox on Webhook inbox, register its URL under Settings › API Access & Webhooks, copy the whsec_ secret, send a test, then verify the delivery here.
  5. When you are done, revoke the test credential.

Use SIT test credentials only. The harness runs the SDK on its server, so it sees the credential while it uses it. It keeps one SDK client per credential in memory for up to 30 idle minutes, so the token cache works, and writes nothing to disk.
